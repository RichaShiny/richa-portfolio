How I think

The model is only one part of the system.

I’m most interested in the layer where modeling meets decisions: what should be automated, how confidence is measured, when a system should escalate, which evidence it needs, and how we know whether the workflow actually got better.

01Start with the decision, not the model.
02Evaluate under the constraints the system will actually face.
03Treat uncertainty, observability, and failure modes as product requirements.
